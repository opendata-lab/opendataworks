# Docker CI 构建优化实施计划

设计：[Docker CI 构建优化](../design/2026-11-03-ci-build-optimization-design.md)。

1. 审查三个现存改动及依赖，确认只转移静态文件、Java JAR，未将本机架构的运行文件复制到目标镜像。
2. 合并工作流中重复的构建/推送步骤，保留 PR 禁止推送和原有标签；缓存按服务隔离。
3. 限制只有 PR 可取消旧任务，保留构建超时与原生 builder 设置。
   同时将两处 Release 动作从 v1 更新为 v2，消除 actionlint 检出的旧运行时问题。
4. 执行 actionlint 和 diff 空白检查，检查 PR/main/tag 事件条件及镜像阶段；记录实际结果。
5. 仅提交三个授权文件与本设计/计划，其他工作区内容不纳入；推送独立分支并用 PR 执行真实双架构 CI。CI 通过后再合并，main 发布链路在合并后验证。
6. 出现构建或发布回归时回退本次提交；不改动现有版本标签与已发布工件。
