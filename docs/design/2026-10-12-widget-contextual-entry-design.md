# Widget 场景入口与 AI 图标设计

## 目标与参考

参考用户提供的腾讯云 Lighthouse 控制台及双闪星 SVG，在父应用关键页面的操作附近提供 AI 助手入口。用户最初限定数据开发、工作流，后续明确扩展为其他页面也显示 AI 助手；最终范围为主应用全部页面。

已从实际页面确认：标题右侧为细边框胶囊，双闪星 + 黑色 AI 助手标签 + 三条轮播场景提示；点击打开悬浮助手并将当前提示预填到输入框，不自动发送。参考的按钮圆角 14px、边框 #e6e9ef、三色图标渐变 #ed63ed/#a36eff/#526cff。保留现有项目字体和布局；提示文字使用更清晰的紫色，减少动态效果，支持键盘和 reduced motion。

## 范围

- frontend：新增通用 AiAssistantTrigger 组件及 floating Widget provide/inject 桥接；Layout 统一页头覆盖全部主应用页面，按所在模块配置提示。
- dataagent/dataagent-frontend：使用用户 SVG 更换悬浮启动图标，扩展 open({ draft })，WidgetChat 消费草稿并聚焦；新增悬浮、左固定、右固定三种面板呈现方式。
- 两个前端各持有一份相同 SVG 资源，避免跨前端打包和部署依赖；不引用腾讯云远程资源。
- 不修改 Java/Python 后端、模型调用、SQL、任务协调、数据库或部署配置。

## 接口与行为

1. controller.open() 保持原行为；controller.open({ draft: string }) 打开并预填草稿。全局 open 便捷 API 转发 options。
2. draftSignal + requestedDraft 采用实例 state；WidgetChat 的 immediate watch 能消费打开前已排队的草稿。不触发 sendMessage、不创建任务或会话、不取消已有后台任务。
3. 父应用 Layout 只创建一个悬浮实例，初始预加载和页面点击共用同一个安装 Promise。通过 inject 暴露 open(draft) 与 isOpen，不使用指向最后安装实例的全局 open。
4. 手动重试脚本加载失败时清理失败的加载 Promise 和脚本，不新增自动重试链。
5. 页面提示每 5 秒轮换；hover、focus、隐藏页面或 reduced motion 时暂停。点击捕获当时的完整文本，长提示在视觉上省略但 aria-label/title 保留。
6. 加载中防止重复点击，失败在按钮附近显示可重试提示，成功以 Widget 打开状态反馈，不增加成功 toast。
7. 数据开发使用建模/SQL/表结构提示；工作流列表、任务、监控使用对应提示；详情携带当前工作流 ID。全部页面入口统一在 Layout 页头中；页头字体跟随主页面，不新增卡片层级。
8. 依用户补充，组件可放在任意位置，通过 prompts 数组配置文案，通过 openAssistant(draft) 函数配置打开动作；未提供函数时使用父应用注入的同一悬浮实例。页面上下文与提示内容属于调用方，不进入轮播组件。

## 统一页头与名称（用户最终反馈）

用户重新选择独立页头布局，要求所有页面采用企业门户统一页头，并使字体与主页面协调。Layout 在所有主应用路由上渲染同一个页头：标题 16px/600，继承主页面字体；主菜单及路由元信息统一为数据开发、工作流。主导航恢复原有 60px 高度，页头保持 44px，不叠加重复的页面级标题。

AI 入口按用户最新要求覆盖全部主应用页面；各模块配置自己的提示，工作流列表页按 route.query.tab 配置，详情提示携带路由中的工作流 ID。移除详情内重复入口。控制台、数据建模、数据集成、设置、巡检移除重复页名，原有功能动作和业务分区标题保留。统一页头下方为独立滚动的内容区；开发工作台高度跟随内容容器，内嵌智能问数继续依据容器位置计算高度。

## 数据开发三栏字体（用户补充）

数据开发左侧目录此前主文字仅 10px，与中间工作区及右侧对象详情不协调。统一使用现有工作台字号变量：主文字/操作/阅读 13px，辅助信息 12px；目录普通行由 24px 到 28px，完整视图行由 36px 到 44px，避免文字变大后裁切。目录节点、查询工具栏、结果工具栏、右侧元数据各 Tab 使用同一变量，编辑器仍保留等宽字体。

## 固定面板（用户补充范围）

保留 displayMode=floating/inline 的挂载契约；浮动实例新增独立 panelMode=floating/docked-left/docked-right，默认 floating。头部菜单切换模式；同一 WidgetChat 不重新挂载，会话、输入、流连接继续保留。固定模式宽度 440px、贴视口边缘并占满高度，禁用拖动/缩放；返回悬浮时恢复原位置和尺寸；小于常规最小尺寸的视口优先保证恢复后的尺寸不越界。关闭后保留模式，下次打开沿用；不增加持久化配置。

controller.setPanelMode(mode)、getPanelMode()、getPanelLayout() 与 panel-layout 事件供父应用接入；事件携带 {mode, side, width, reservedWidth, isOpen}。width 是可见面板宽度，reservedWidth 是建议预留宽度，窗口小于 1024px 时为 0，采用覆盖呈现以避免主页面被压窄。父应用 Layout 监听自己实例的事件，在两侧留空间；关闭或销毁恢复布局。Widget 不直接修改未知宿主的 DOM。inline 无菜单、setPanelMode 返回 false。支持脚本 data-panel-mode 和程序配置 panelMode；非法配置归一化为 floating，非法运行时设置返回 false。

## 验证与边界

针对草稿首次打开、重新预填、实例隔离、未发送、单次安装并发、轮播暂停及异常重试增加聚焦测试；验证固定模式会话/草稿保留、菜单键盘操作、几何恢复、关闭/销毁释放父应用空间。两个前端生产构建；真实浏览器验证数据开发/工作流头部入口、草稿与聚焦、全屏交接以及按钮 320/375/414/768px 适配。浏览器测试采用模拟 HTTP 时明确说明；不声称真实模型运行或后台任务恢复已验证。

回退为移除页面入口与 bridge、恢复启动 SVG、撤销 open 参数扩展。没有持久化或数据迁移。
