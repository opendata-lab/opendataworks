## Scope

本次只解决两件事：

1. 采集对象的范围预览与实际采集统一使用数据源配置中的平台连接账号，让用户在执行前就知道该账号能采集什么。
2. 顶部为数据开发、数据治理、智能问数、管理中心四项；开发/治理/管理左侧用 Element Plus 菜单组织现有功能，智能问数独立打开。数据地图归数据治理，元数据采集与血缘归地图；数据集成保留业务数据同步，移除其数据源配置及替代链接。

用户已在完成设计与计划后明确要求开始实施。导航按用户最新层级归位，但不实施此前讨论的详情体系、工作流/运维业务拆分或新资产功能。此次不新建资产目录、表详情、任务详情、运行实例详情、通用页面状态存储、目录权限体系或独立采集器模型；不拆工作流，不改血缘画布业务与建模；血缘只调整入口归属。

## Problem

用户账号与采集账号权限不同本身可以成立。当前问题是页面先按用户身份发现表，再让用户以为可以直接采集，而实际采集换了身份。

本次不要求两个账号权限完全相等，不把所有查询改用采集账号，也不以用户账号替代定时采集账号。目标是让每个动作从选择对象到执行都遵循同一身份，并在越过职责边界时明确提示。

## Design

### 1. 保留两种身份，统一采集操作的身份

| 操作 | 使用账号 | 界面表达 |
| --- | --- | --- |
| Data Studio 实时树、查询、结构操作 | 当前用户映射的数据库账号 | 你能访问的数据库对象 |
| 采集范围预览、比对、手动与自动采集 | 数据源配置的平台连接账号 | 平台能够采集的数据库对象 |

元数据采集页展示“采集使用账号：opendataworks（来自数据源配置）”，只读、不显示密码；修改账号回数据源管理。数据源表单的用户名说明补充“用于平台采集与后台检查；个人访问使用账号映射”。

SQL 页面不再直接调用采集接口。用户看到未采集表时，显示“该表尚未采集到平台，查询不受影响”；管理员提供“去采集元数据”。不因为用户可见就承诺采集可见。

### 2. 最终导航与布局：顶部四项，复用现有页面

顶部四项在完整顶栏中线居中，品牌与用户入口分别居左、居右；窄容器不够时导航内部横向滚动。顶部沿用现有横向导航区域，保留数据开发、数据治理、智能问数、管理中心四项。开发/治理/管理的左侧使用 Element Plus `el-menu / el-menu-item / el-sub-menu`，右侧渲染既有页面；智能问数保持当前独立远程嵌入页，不加空侧栏。控制台继续保留为现有首页，由首页/品牌入口返回，不扩成新的业务模块。

```text
数据开发
  数据开发        → 当前 SQL 工作区
  数据集成        → 当前 DataX 数据同步任务
  数据建模        → 当前业务域 / 数据域管理
  任务调度        → 当前工作流页面（工作流 / 任务 / 执行监控 Tab 保留）

数据治理
  数据地图
    资产目录      → 尚无独立页面，本次不显示
    元数据检索    → 尚无独立页面，本次不显示

    数据血缘      → 复用 LineageView
  数据质量        → 当前巡检 / 质量页面

智能问数          → 顶部独立入口，当前远程嵌入页

  数据源          → 当前连接 / 账号映射 / 默认与停用 / 备份

  MinIO 管理      → 当前 MinIO 环境
```

上图列出目标职责与未实现项。实际菜单只渲染可用且有权限的功能：地图先显示元数据采集、数据血缘；资产目录与元数据检索不加占位、禁用项或新页面。现有 SQL 实时树不是资产目录，也不直接作为元数据检索页复用。

#### 菜单与业务边界

- 数据开发的“数据开发”保留用户命名，实际就是 SQL 工作区；对象实时树、执行、结果和技术详情不改。
- 数据集成直接展示当前 DataX 任务，不再套一层只有“数据同步”的子菜单或旧顶部 Tab；源配置从这里移除，不留替代管理链接。
- 数据建模仅承载现有业务域/数据域管理，不补模型画布、指标等功能。
- 任务调度只是当前工作流模块的新菜单名称；原工作流、任务和执行监控 Tab、详情、发布、Cron、补数均保留，不拆成开发/运维两套页面。
- 元数据采集集中范围预览、比对/执行、自动同步/Cron、历史与待删除表；只同步元信息，不搬业务记录。数据血缘只调整菜单归属，图、中心表/深度参数及现有详情跳转不重做。
- 管理中心是唯一源配置入口；“调度引擎”先对应 Dolphin 配置，不代表已支持通用多引擎管理；MinIO 和助手配置继续复用。智能问数保留顶部独立使用入口，治理侧栏不重复；智能助手是管理配置，两者不混放。

#### 只增加一层共用模块导航

左侧菜单在 `Layout.vue` 统一提供，按路由归属切换菜单数据，不为开发、治理、管理各建立一份独立壳。设置页删除自身的自定义导航按钮，只保留内容选择；数据集成也删除自身顶栏/单项侧栏，避免形成双重导航。

允许新增一份明确的导航配置，集中记录模块、菜单和路由映射，避免在多个页面复制判断；不引入通用页面状态存储或新业务框架。数据地图是数据治理侧栏的子菜单分组，不需要新增 DataMap 页面容器。

SQL 工作区原对象树和任务调度原业务 Tab 分别承担对象定位与业务视图切换，继续保留；它们不是另一套模块菜单。模块侧栏应可收起，为 SQL/血缘画布保留宽度。右侧沿用当前密度、浅边框及 Element Plus 样式，不展开视觉重设计。

### 3. 数据地图与数据资产的概念边界

“数据地图”是功能模块；“数据资产”是被纳管的表、视图等对象。若用作页面名称，“数据资产”通常指这些对象的目录/搜索列表，可作为地图内部视图，不应与地图再维护一套表元数据。

| 概念 | 用户要解决的问题 | 本次范围 |
| --- | --- | --- |
| 数据地图 | 到哪里发现、理解数据及其关系 | 数据治理左侧的菜单分组，复用现有能力 |
| 数据资产 / 资产目录 | 有哪些表，它们的结构、说明和归属是什么 | 现有平台表元数据是基础；本次不新增独立列表或详情 |
| 数据血缘 | 表从哪里来、流向哪里 | 复用原血缘页面 |
| 元数据同步 / 采集 | 怎样把数据库结构接入并更新到平台 | 本次身份一致性修复与独立操作入口 |

DataWorks 另有“数据资产治理”，侧重健康度、质量/安全问题、存储与计算成本等治理工作，不能与普通资产目录混称。本次不引入该治理模块。参见[数据地图概述](https://help.aliyun.com/zh/dataworks/user-guide/data-map/)、[数据资产治理概述](https://help.aliyun.com/zh/dataworks/user-guide/data-asset-governance)。

本次地图菜单只有现有血缘与元数据采集，不添加未实现的“数据资产”占位菜单，也不扩回此前的完整资产详情方案。

### 4. 元数据采集页布局与执行前检查

```text
元数据采集       数据源选择
同步表结构等元数据，不搬运业务记录
采集使用账号 / 引擎 / 地址（只读）
本次范围：全源 / 单库 / 单表
库、表选择（使用采集账号加载）       [刷新范围]
权限/连通性与目标对象检查结果
                                 [比对] [开始采集]
自动同步：开启 / Cron（周期范围明确为全源）
运行历史（复用当前历史列表及详情弹窗） / 待删除表
```

数据源、库、表选项全部由采集账号加载。单表深链可以带入 Data Studio 中看到的对象，但要按采集账号重新检查：

1. 用户账号能看到 `dataagent.aq_chat_message`，进入采集页时预选该数据源、库与表。
2. 采集账号未查到时，保留目标名称并显示“采集账号 opendataworks 未发现该对象，请检查账号权限或表是否存在”，禁用本次执行。
3. 管理员修正连接或数据库授权后，手动刷新范围再执行。

数据库会按权限隐藏对象，不能仅凭未列出就断言物理表不存在。普通连接成功也不代表目标库/表具备采集权限。预览检查仅确认选择时可见；执行期间权限或结构变化仍以同步服务的最终结果为准。

手动单库/单表选择只对本次生效；自动采集继续使用平台账号可见的全源范围，不新增持久化范围字段、多采集器或调度引擎。

### 5. 跳转与已有编辑现场

| 来源 | 目标 | 行为 |
| --- | --- | --- |
| 管理中心左侧“数据源” | `/settings?tab=datasource` | 维护连接的唯一入口 |
| 数据源“元数据采集” | `/metadata-sync?sourceId=...` | 预选源，不自动执行 |
| 数据治理 / 数据地图 / 元数据采集 | `/metadata-sync` | 打开已有源选择与元数据范围/历史 |
| 数据开发 / 数据集成 | `/integration` | 保留现有 DataX 任务页，不继承元数据源上下文 |
| SQL 未采集表“去采集元数据” | `/metadata-sync?sourceId=...&database=...&tableName=...` | 新浏览器标签打开，保留原 SQL/对象标签 |
| 任务抽屉现有“去同步” | 同一元数据采集页；仅携带已知对象定位 | 新浏览器标签打开，保留任务表单，不新增草稿存储 |

元数据采集缺连接时仅展示管理中心路径指引，不嵌入源配置；数据集成不放配置链接。处理账号权限后回此页刷新范围。同步后回原页由用户刷新目录或重新分析任务；不做自动回写、自动保存、自动发布或跨窗口事件同步。URL 不含 SQL、密码和其他凭据。sourceId 为明确目标，不以默认数据源代替；后端重新校验目标归属与权限。

### 6. 成功、失败与刷新分开反馈

- 执行结果为 SUCCESS 才显示“元数据采集成功”；PARTIAL 显示部分成功及错误，FAILED 显示失败。沿用现有服务返回，不能只判断 HTTP 200 或 Result 信封。
- 单表 SUCCESS 后刷新目录并验证平台表。刷新失败或未找到表时显示“采集结果待核实”，说明后端报告成功但目录验证未完成；不把后端成功记录改成失败，也不显示已验证成功。
- 请求超时显示“结果未确认，请查看同步历史”，不盲目重试。现有历史查询足以人工确认，不新增后台作业与轮询系统。
- 运行历史继续显示原状态、错误和变更；lastSyncTime 改为准确的“最近自动触发”文案，不为了新统计增加接口。
- 比对返回 errors 时不能显示“结构一致”。现有比对可能更新统计，文案不称完全无副作用。
- 采集账号变化后重新加载范围，连接测试、保存配置与执行采集分别反馈；不默认执行创建后的首次采集。

### 7. 只保护相关入口

范围预览、采集配置和系统采集操作按现有 admin 角色保护；前后端同时限制，不能仅隐藏按钮。用户/智能体账号映射沿用当前规则。

本次不重构全平台 RBAC、元数据可见性或任务权限。普通用户原有实时树与查询仍受自己的数据库 GRANT 约束。不能为了让范围看起来一致，扩大普通用户权限或自动使用 root。

## Interfaces / Data Model

只在已有 DorisClusterController 增加两个小接口，不新建 Catalog/Collection 控制器和服务体系：

| 接口 | 职责 | 约束 |
| --- | --- | --- |
| `GET /v1/doris-clusters/{id}/metadata-scope?database=...`（新增） | 无 database 时列库，有值时列该库的表 | admin；显式源 ID；通过 `withSystemAccount` 与现有适配器读取，不改变原用户目录接口 |
| `PUT /v1/doris-clusters/{id}/metadata-sync-config`（新增） | 更新 autoSync / syncCron | admin；仅更新采集列，保留现有开启自动采集时初始化触发基准的行为 |
| 现有 `/v1/tables/sync-metadata...`、`audit-metadata` | 全源/库/表采集及比对 | 复用，同样校验 admin 和源状态，避免直接请求绕过入口 |
| 现有 `/v1/doris-clusters/{id}/sync-history...` | 历史与明细 | 复用现有响应及弹窗，不新建运行详情路由 |

范围响应：`{accountUsername, database, databases, tables}`；无 database 时填 databases，有 database 时填 tables，另一集合为空。表结构复用现有目录 DTO/Map。密码不进入响应，账号名只对管理员展示；无法读取时明确失败，不以空数组掩盖异常。

配置请求只接受 `{autoSync, syncCron}`；复用现有校验与数据源服务，按列更新，不能让保存 Cron 覆盖连接信息。数据源普通编辑保留已存采集字段，不提交旧 autoSync/Cron 值，不形成两个表单相互覆盖。

沿用现有实体、同步服务与 history；不改数据库结构、定时调度方式和 DataAgent；不修改 Dolphin 数据源或把两边账号配置自动绑定。

## Risks / Alternatives

- **把两个账号改成同一个**会改变个人权限与后台任务的职责；本次保持两种身份，只统一采集内部预览和执行身份。
- **把 SQL 树改成采集目录**会限制开发者看到新表，本次保留用户实时树。
- **只修改失败提示**不能在选择时揭示采集范围，本次加同身份范围预览并分离采集入口。
- **门户全量重组**与当前问题无直接依赖，已从本次计划移除。独立表/任务/实例详情、血缘/建模重构与全局状态机制均不实施。
- **预览与执行之间撤权**无法靠前端永久保证；执行服务继续报告真实结果，禁止账号回退。

## DataWorks 采集页交互参考补充

2026-10-29 用户要求参考 DataWorks 元数据采集界面。按[当前官方说明](https://help.aliyun.com/zh/dataworks/user-guide/metadata-collection/)核对，其核心组织为采集列表进入详情，详情区分基本信息、数据范围、运行日志。本项目参考该信息层次，保留现有一源一份采集配置；不新增采集器实体、保存范围、多资源组或任务停止能力。

前端 `/metadata-sync` 无 sourceId 时显示已有数据源的采集列表，支持按名称/账号搜索和源类型筛选。列出数据源、类型、采集账号、采集计划和源启停状态；不把数据源的调度基准时间误当成功运行时间。名称/“配置采集”进入该源详情，行内“运行记录”进入历史页签。

详情采用白底平铺结构，顶部返回采集列表、源名称/类型和源状态；下方三个 Element 页签：基本信息（只读连接与账号、周期配置）、数据范围（现有手动范围与执行/比对/结果）、运行记录（已有历史表格/分页，明细仍用原弹窗）。来源选择与数据库/表深链保留：有 database/tableName 默认打开数据范围；sourceId 单独指定默认基本信息；运行记录使用 tab=history。当前范围只影响本次执行，周期仍全源，在对应区域明确说明。

仅修改现有 Vue 视图和定向交互测试，不改后端/API/数据库或独立 DataAgent。采集、配置、比对期间保留路由离开保护；从列表进入和返回均由现有路由 query 驱动，避免另存一份当前源状态。历史请求迟到或失败不得显示为其他源的记录。账户可见性、成功判定与新标签返回规则继续沿用前述设计。
