# 元数据采集与数据源管理

数据源连接统一在 **管理中心 → 数据源** 维护，包括数据库类型、地址、平台连接账号、个人账号映射和结构备份。数据集成只保留 DataX 数据同步任务。

管理员通过 **数据治理 → 数据地图 → 元数据采集** 进入采集列表，支持搜索数据源名称/采集账号及按类型筛选。每个已有数据源对应一份采集配置，点击名称或“配置采集”进入详情。页面展示采集账号，库表预览、比对、手动和自动采集均使用数据源配置中的平台连接账号。账号调整仍在管理中心完成，采集页没有第二份连接配置。

## 页面布局

采集详情分为三个页签：

- **基本信息**：查看源类型、地址、采集账号，保存按需/周期采集计划；“修改数据源”打开管理中心中的该源。
- **数据范围**：用采集账号预览范围，执行一次手动采集或全源比对。周期采集始终覆盖全部可见范围。
- **运行记录**：查看真实历史和分页，点击“详情”查看错误与变更明细；加载异常会明确提示，可刷新重试。

“返回列表”回到数据源采集列表；“待删除表”保留原恢复/清理入口。`/metadata-sync?sourceId=...` 进入基本信息；附 database/tableName 时默认进入数据范围；`tab=history` 直接进入运行记录。切换页签保留当前库表目标和未保存的计划，只有点击保存才提交。

## 手动采集

1. 从列表进入目标源的“数据范围”页签，等待平台账号可见范围加载完成。
2. 选择全部可见数据库、指定数据库或指定表。指定范围仅对本次手动操作生效。
3. 点击“开始采集”并确认账号与范围；如需比对，使用“比对全源元数据”。
4. 根据业务状态查看结果。SUCCESS 表示后端成功；单表操作还会刷新平台目录并核对目标表。PARTIAL/FAILED 不显示成功，目录刷新失败显示“待核实”，请求超时显示“结果待确认”，请查历史后决定是否重试。

采集历史包含运行状态、范围、错误及变更明细；“待删除表”保留原来的恢复和清理功能。历史在执行结束后写入，超时后若尚无记录，应稍后再查，不能据此认定任务未执行。

## 自动采集

按需/周期触发方式和六段 Spring Cron 在“基本信息”的采集计划中保存，每次覆盖平台账号全部可见范围；不保存手动库/表选择。连接编辑与采集配置分别更新，互不覆盖。`lastSyncTime` 仍是自动触发基准，成功与否以采集历史为准。

## 为什么 SQL 目录和采集范围不同

SQL 工作区继续使用当前用户的个人映射账号直连数据库。它展示个人能访问的对象，平台尚未采集的表也可以查询；平台资产元数据相关操作需要先采集。

例如个人账号能看 `dataagent`，平台账号无权访问：SQL 树仍显示它，采集页不会把它列为可选范围。从 SQL 工作区或任务抽屉进入采集时会在新标签页打开，保留已有 SQL/表单；若目标对平台账号不可见，页面保留目标名称、说明原因并阻止采集。采集后回原标签手动刷新目录或重新解析 SQL。

请按真实数据库选择类型：MySQL 应配置为 MySQL；账号能登录不代表拥有目标库权限。仅修改个人映射不会改变平台采集账号权限。管理员处理源配置与授权，普通用户继续按自己的数据库账号访问。

## 导航

- 数据开发：SQL 工作区、数据集成、数据建模（现有业务域/数据域管理）、任务调度（现有工作流/任务/执行监控）。
- 数据治理：数据地图下的元数据采集/数据血缘、数据质量。
- 智能问数：保留顶部独立入口。
- 管理中心：数据源、调度引擎（DolphinScheduler 配置）、MinIO 管理、智能助手。

资产目录、独立元数据检索等未实现功能暂不显示。主要旧路由继续可用，新增采集入口为 `/metadata-sync`。
