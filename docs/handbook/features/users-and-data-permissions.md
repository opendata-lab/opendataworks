# 账号与数据源权限

平台管理员在「管理中心 → 账号管理」管理登录用户，在「管理中心 → 数据源 → 权限配置」管理每个源的成员和角色。平台管理员身份用于配置权限，不自动获得数据查询权限。

## 账号类型与Token

新建时选择普通用户或服务账号，创建后类型不可变。普通用户有登录信息；服务账号只填名称与用途，后台生成稳定标识，没有登录密码、邮箱或平台管理员权限。服务账号只用于程序接入，不能网页登录。数据源授权用户只选择普通用户，授权服务账号只选择本平台已有且启用的服务账号，均不读取DataAgent列表或手填助手ID。

服务账号行「管理Token」可新建及撤销Token；有效期1～365天，默认90，允许多个并存以便轮换。明文仅创建时展示一次，关闭后不能再次查看；名称、前缀、到期、撤销和最后使用时间可长期查看。平台只保存Token摘要，不保存明文。停用或删除账号后所有Token不能再认证，启用后已撤销Token仍无效。停用账号不能生成新Token，但管理员可查看并撤销已有Token。时间按UTC保存和比较、接口带时区返回，页面显示浏览器本地时间。

外部应用配置MCP地址与`Authorization: Bearer <服务Token>`；平台据此识别服务账号，不需要DataAgent内部agent_id。V57会把已有AGENT数据源绑定迁为真实服务账号并保留数据库权限，管理员需生成Token并更新外部MCP配置，旧共享Token不再有效。内部转发服务密钥不等于服务账号Token。

## 普通用户管理

可创建本地用户、编辑姓名／邮箱／平台角色、启停、重置密码及删除。创建用户不会隐式授予数据权限；授权用户弹窗也可先创建用户，再分配源内角色。两次保存分别报告结果，角色分配失败时保留已创建的用户。

本地用户名创建后不能修改，已删除的用户名不复用。密码至少8位，UTF-8编码最多72字节，以BCrypt哈希保存，不回传。第三方账号不设置本地密码。停用、删除和改密立即使原登录会话失效，重新启用不恢复旧会话；平台角色变更在下一次请求生效。不能停用、删除或降级当前管理员，至少保留一个启用的管理员。

停用／删除仅阻止平台访问，不自动删除数据库登录账号或撤销DBA已有权限。需撤销原生权限时，先在对应源的成员页移除成员；数据库直连账号的停用／删除由DBA处理。

## 配置一个源

1. DBA准备授权管理账号，以及每个普通用户／服务账号独立的数据库登录账号。平台不自动创建或删除数据库登录账号。
2. 打开源的「权限配置」。默认管理连接使用源配置账号；权限不足时，在「授权管理连接」填写专用管理账号。它只用于资源盘点、原生授权和核验，不作为业务查询回退。保存专用连接前须配置服务端密钥，见[部署说明](../../../deploy/README.md#users-and-data-permissions)。
3. 在「角色」新建角色。只读／读写／数据管理员是权限模板；选择库／Schema、表或视图，勾选需要的动作。模板不创建共享登录账号，也不自动授予所有资源。
4. 「预览并保存」展示本次原生SQL、影响成员和数据库限制。确认后立即执行并回读；仅数据库与平台记录均成功才显示成功。预览有效期10分钟，状态变化后需重新预览。
5. 在「成员」授权已有普通用户或平台服务账号，勾选一个或多个角色，再绑定该成员的一个数据库账号。同源每个账号只能绑定一个成员，避免角色分配相互影响。未绑定时明确显示「待绑定账号」，不能查询。

一个成员账号持有多个原生角色，因此同一连接可以跨已授权的库／Schema关联查询。权限以底层数据库最终判断为准。查看「实际权限」可核对已有直接授权和外部角色；平台不会自动撤销这些外部授权，它们可能扩大有效范围。

## 统一操作与原生差异

| 界面操作 | MySQL 8 | PostgreSQL 16+ | Doris |
| --- | --- | --- | --- |
| 查询 | SELECT | SELECT，加必要Schema USAGE | Select_priv |
| 写入 | INSERT、UPDATE、DELETE，可细分 | INSERT、UPDATE、DELETE，可细分；SERIAL列补必要序列USAGE | Load_priv组合能力，不拆成单一INSERT |
| 创建对象 | 库级CREATE | Schema CREATE | Create_priv |
| 修改／删除对象 | 按支持范围ALTER／DROP | 对象所有权控制，不伪造独立GRANT | Alter_priv／Drop_priv |
| 查看视图定义 | SHOW VIEW | 不提供独立动作 | 按引擎能力显示 |

角色配置只展示当前引擎和资源支持的动作。不提供业务「转授权」开关；Doris Grant_priv不等于写入权限。服务账号只允许查询／只读角色，绑定时检查原生账号已有写入、所有权和管理能力，不能以平台只读标签替代底层隔离。

MySQL／Doris库级授权通常包含未来对象。PostgreSQL Schema查询／写入展开为当前对象，未来新表不会自动加入；不修改创建者的默认权限，不转移所有权。视图可更新性与最终执行能力仍由数据库决定。

MySQL 8.0.45在partial_revokes关闭时，含下划线或百分号的库名有原生角色Bug110582：库级授权预览明确拒绝，仍可按精确表／视图授权。平台不会去掉转义扩大范围，也不会修改数据库全局设置。[实际限制](../../design/2026-10-26-dataagent-datasource-identity-design.md#105-实测mysql库名通配符限制2026-11-01)。

## 失败、撤销与审计

「授权记录」保留操作者、资源、SQL步骤、回读与结果。FAILED表示明确失败，PARTIAL表示部分步骤已生效，UNKNOWN表示无法确认；不能按失败提示假定数据库未变化。失败预览重复提交不会自动重放，需核对原生状态后重新预览、明确确认。

涉及不一致的角色／成员会阻止相关账号继续查询，其他角色仍可使用；无全源「待同步」或后台授权同步任务。角色资源、成员分配和账号绑定均在当前请求内执行原生变更并核验。管理记录和业务库不构成分布式事务。权限服务短事务使用READ_COMMITTED，已有每源锁串行同源修改，不改变平台全局隔离级别。

移除成员会撤销本平台托管的原生角色，保留数据库登录账号与外部权限。V56保存绑定时验证的实际数据库身份，已绑定成员即使密码过期，仍可通过管理连接撤权。升级前的老成员尚无该身份时，重新绑定一次；存在托管角色但无法解析旧身份的情况会明确报错。删除仍有成员的角色被拒绝；PostgreSQL先撤销托管ACL再删除ROLE，不执行DROP OWNED或CASCADE。

## 智能问数

本期服务Token限定元数据与只读查询接口，不能调用开发写接口。问数服务账号沿用只读角色与原生受限数据库账号。无用户头时以服务账号自身权限工作；提供用户身份时，人的账号先EXPLAIN、服务账号执行，元数据取双方交集。未知或停用用户不会退回服务模式。

签名用户委托仍延期：服务Token已认证调用的服务账号，不代表已证明它上报的自然人是谁；未签名用户头仍仅适合可信内网，不宣称生产可信代人授权。
