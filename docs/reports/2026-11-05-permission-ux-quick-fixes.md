# 数据源权限中心交互快速修复

日期：2026-11-05。来源：管理员反馈权限分配、用户与角色流程"不顺畅"；由 Gemini 4 Argon 只读走查前端代码，Claude 逐条核对代码后修复局部问题。整体信息架构调整登记于[统一待办](../TODO.md#权限中心交互体验2026-11-05-ux走查)。

## 修复内容

1. **新建角色不再自动生成整库授权草稿**。此前创建模板角色后，若矩阵已选中某库，会静默把该库的 SCHEMA 级模板动作写入草稿；管理员只勾一张表并保存时，整库权限会一并提交。现在新角色从空草稿开始，提示勾选资源后预览保存。
2. **角色摘要显示具体对象**。授权与分配角色弹窗中的角色摘要此前只按库聚合，整库授权与单表授权显示相同；现按"库 + 动作集合"分组显示 `库.*` 或 `库.表`，每组最多列 3 项，超出显示"等 N 项"；不同动作的对象分开列出，避免把单表的写权限显示到整库或其他表上。
3. **授权记录显示名称**。对象列与操作人此前显示内部数字 ID（如 `USER：42`），现按平台账号映射为用户或服务账号名称；查不到时仍显示原 ID。
4. **分配角色不能保存为空**。与"授权成员"至少选一个角色保持一致；需要收回全部权限时提示使用"移除"。
5. **从角色"管理成员"进入授权时预选该角色**。授权已有成员时改为追加所选角色、保留其原有角色：此前授权请求按全量角色集合提交，选中已是成员的用户会收回其他角色（评审发现，预选角色会放大该问题）。调整全部角色仍使用"分配角色"。
6. **删除未使用代码**。`isWriteRole` 与 `isRoleAssignedToService` 已无任何使用方（按设计服务账号可以分配读写角色，现有测试已覆盖），一并删除。

后端、API 与数据模型均未改动。
