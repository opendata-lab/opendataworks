# Data Studio 功能接线核查

检查日期：2026-10-10。范围：当前4174页面、正式Vue前端的入口/事件/inject/API、相关Java控制器路由、现有回归测试。本轮仅检查并记录，未修改功能代码。

## 结论

当前页面仍是演示构建：`VITE_DEMO_MODE=true` 时，`frontend/src/utils/request.js:13` 将请求替换为 `demoAdapter`，不会访问真实Java API。因此当前可操作程度不能代表正式环境功能接通程度。检查时本机只有4174监听，未发现8080 Java API或3316 MySQL监听。

在本次检查范围内未发现重构后按钮缺少事件绑定或对应注入方法的情况；存在以下可复现不一致和功能联动缺口。

## 已确认的问题

| 项目 | 当前表现与依据 | 建议 |
| --- | --- | --- |
| 新鲜度编辑/保存 | 演示页面允许进入编辑并点击保存，实测报“演示环境仅支持浏览与查询”；mock只有查询/历史/检查，没有PUT/DELETE实现 | 演示入口明确只读，或补充隔离的本地演示状态；正式保存路由已有 |
| 新鲜度立即检查 | 实测提示“检查完成”，但检查时间仍为2026-03-11 10:30:00；mock检查返回固定结果，随后GET又返回固定旧结果 | 若演示此操作，检查后更新演示状态及历史，并标明样例 |
| 存为任务的数据源联动 | `useTableActions.js:42`只传taskSql/taskName/taskDesc，连接和数据库仅写入描述；`TaskEditDrawer.vue:840`只接收这三个预填字段，任务数据源仍为空 | 明确门户连接与调度数据源的映射，匹配后预填；无法匹配时要求选择，不能按名称盲猜 |
| 引擎属性的编辑入口 | 头部编辑入口只在basic/columns；引擎页分桶/副本输入依赖metaEditing，需先在概览进入编辑再切到引擎配置 | 改为直接从引擎页进入既有元数据编辑，保留引擎限制提示 |

新鲜度正式接口已经存在：`tableApi.saveFreshness/checkFreshness/deleteFreshness` 对应 `DataTableController` 的PUT/POST/DELETE路由，并非后端路由缺失。

## 状态切换的潜在问题

以下来自源码检查，本轮未通过慢接口现场复现，需针对性验证，不能当成已复现故障：

- 新鲜度组件的异步读取直接写共享resp，没有请求序号/目标表校验。快速从A表切到B表时，A的迟到结果可能覆盖B；B加载失败时旧resp也未清空。依据：`DataStudioRightPanelFreshness.vue:323`。
- 分区加载使用组件级partitionsLoading。A仍加载时切B，B的watch触发后直接返回；A完成不会自动重试B，B可能要手动刷新。依据：`DataStudioRightPanelDoris.vue:134`。
